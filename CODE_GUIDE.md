# Как читать код wave

## С чего начать

1. `src/main.tsx` — запуск React и порядок подключения стилей.
2. `src/App.tsx` — состояние приложения, координация плеера, навигация и подключение экранов.
3. `src/HomePage.tsx` — главная страница и подборки музыки.
4. `src/CollectionManager.tsx` — списки песен, выбор нескольких записей и действия с коллекцией.
5. `src/ProductSettings.tsx` — настройки, резервные копии, память и инструкция для iPhone.

## Важные правила плеера

- В приложении используется один постоянный `<audio>`. Переход между экранами его не пересоздаёт.
- Воспроизведение запускается действием пользователя. Восстановление страницы возвращает плеер на паузе.
- Счётчик `seq` отличает актуальную загрузку от устаревших асинхронных операций. Не удаляй эти проверки при изменении плеера.
- Сохранённая позиция применяется после загрузки метаданных аудио.
- Сетевые повторы ограничены. Ручная пауза отменяет автоматическое продолжение.
- Ключи `volna.*` сохранены для совместимости с уже существующей библиотекой. Переименование приложения в wave не требует их менять.

## Стили и их порядок

Порядок импортов в `main.tsx` влияет на каскад CSS:

1. `style.css` — базовая раскладка и основные элементы.
2. `wave.css` — фиолетовая тема и визуальные эффекты.
3. `library.css` — библиотека, карточки коллекций и фон.
4. `product.css` — расширенные экраны, настройки и доступность.

В каждом файле свойства записаны отдельно, а адаптивные правила находятся в блоках `@media`. Не переставляй файлы или CSS-правила без проверки внешнего вида.

## Скрипты и проверки

```powershell
npm.cmd run dev           # Локальная разработка
npm.cmd run format        # Оформить исходники единообразно
npm.cmd run format:check  # Проверить оформление без записи
npm.cmd run check         # Проверить поведение модулей и компонентов
npm.cmd run build         # TypeScript, сборка и подготовка офлайн-кэша
```

Браузерные сценарии запускаются с работающим `npm.cmd run preview -- --port 4173`:

```powershell
node tests/product-browser.mjs
node tests/browser.mjs
```

`scripts/finish-build.mjs` подставляет собранные JS/CSS в список `PRECACHE_ASSETS` сервис-воркера. Обновляй шаблон и сборщик вместе. Наличие маркера проверяется при сборке, чтобы форматирование не могло незаметно сломать офлайн-режим.

## Что редактировать

Редактируй `src/`, `public/`, `scripts/`, `tests/` и конфигурацию проекта. Папки `dist/`, `node_modules/` и `qa/` содержат результаты сборки, установленные зависимости и материалы проверок — их не нужно форматировать или править вручную.

Формат задают `.prettierrc.json` и `.editorconfig`: UTF-8, отступ в два пробела и единое оформление. Комментарии описывают назначение блоков и причины нетривиальных решений; поведение проверяется тестами.

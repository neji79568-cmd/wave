# Волна

Музыкальный PWA-плеер на React, TypeScript и Vite. Тёмный интерфейс в духе Spotify, адаптированный для iPhone и компьютера. Внутри приложения нет регистрации и подписки.

## Запуск на Windows

В этой папке выполните:

```powershell
npm.cmd install
npm.cmd run dev
```

Для просмотра на iPhone подключите устройства к одной Wi-Fi сети и откройте Network URL, который напечатает Vite. Для установки PWA, сервис-воркера и офлайн-запуска на iPhone нужен HTTPS-хостинг. Обычный HTTP по локальной сети подходит для проверки интерфейса и онлайн-аудио, но не для полноценного офлайн-режима.

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run preview
```

Готовый статический сайт находится в `dist/`. Эту папку можно разместить на HTTPS-хостинге. Пути относительные: сайт поддерживает размещение в подпапке.

## Музыка и ограничения

- Audius: поиск, популярные треки и полные доступные аудиопотоки без ключа. Платные, закрытые и недоступные записи исключены. Это каталог пользовательских загрузок; название записи не подтверждает её официальность.
- iTunes Search: поиск мировых исполнителей и только ознакомительные фрагменты. У каждого трека видна отметка «Фрагмент», оригинал открывается из полного плеера. Это не доступ к полной библиотеке Apple Music.
- Свои файлы: MP3, M4A и другие поддерживаемые браузером аудиоформаты сохраняются в IndexedDB. Они не отправляются на сервер. После загрузки оболочки PWA по HTTPS доступны офлайн. Поддержка формата зависит от Safari.
- Наличие «всех песен мира» и конкретных новых релизов не обещается. При проверке 22 ноября 2026 года точный запрос `Miyagi На дне` в Audius не дал результатов.
- Избранное, плейлисты и история сохраняются в localStorage в текущем браузере. Синхронизации между устройствами нет. Очистка данных сайта удаляет библиотеку; браузер также может освобождать хранилище.
- Используется один постоянный HTMLAudioElement, Media Session API и Audio Session playback, если браузер поддерживает. Переключение страниц приложения не прерывает песню. Фоновое воспроизведение, управление с экрана блокировки и автоматический переход между треками на реальном iPhone пока не проверены. JavaScript может приостанавливаться системой. Громкость на iPhone может регулироваться только аппаратными кнопками.
- PWA не требует собственного сервера. Размещённое на Sites личное превью может требовать входа в существующий ChatGPT-аккаунт на уровне хостинга; в самом приложении входа нет. Для ссылки совсем без входа требуется общедоступный HTTPS-хостинг.

## Проверено

- Production-сборка TypeScript/Vite.
- Сценарий с тестовым аудио: поиск, запуск/следующий трек, избранное, создание плейлиста, добавление песни, фрагменты, полный плеер и восстановление библиотеки.
- Сохранение, чтение и удаление локального файла в IndexedDB.
- Живой поиск Audius/iTunes, CORS-заголовки и реальный аудиопоток Audius: HTTP 206, audio/mpeg, чтение первых 1024 байт.
- Headless Chrome на Windows: настоящее воспроизведение Audius, избранное, экраны 1440 и 393 px без горизонтального переполнения, импорт WAV, перезагрузка страницы без сети и воспроизведение сохранённого файла офлайн. Скриншоты и отчёт создаются в игнорируемой папке `qa/` командой `node tests/browser.mjs` при запущенном `npm.cmd run preview -- --port 4173`. Скрипт использует установленный Chrome по стандартному Windows-пути.
- Проверки DOM не заменяют проверку внешнего вида и фонового воспроизведения на физическом iPhone.
